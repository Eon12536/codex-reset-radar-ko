## 0.2.24 계정 기록 동기화

설정 → 감시 설정 → **Chat 계정 연결 및 모델별 카운터**를 켠 뒤 **계정 기록 동기화 · 다른 기기 포함**을 켜세요. 계정에 저장된 최근 30일 기록에서 Astra·Sol Pro 응답을 집계합니다. 데스크톱·휴대폰·설치 전 기록도 같은 계정에 동기화돼 있으면 확인 범위에 포함됩니다. 기존 Chrome 관측과 같은 응답은 한 번만 셉니다.

- 팝업의 **지금 동기화**에서 수동 확인할 수 있습니다. 마지막 확인 시각·일부 확인·모델/시각 미확인·로그인/연결 오류를 표시합니다.
- 한 번에 최신 활성/보관 목록 각각 100개, 새 상세 최대 20개, 대화별 최대 3페이지를 확인합니다. 확인하지 못한 대화는 이후 확인에서 이어가며, 한도에 걸린 목록·메시지는 일부 확인으로 표시합니다.
- Chrome이 꺼져 있으면 다음 실행 때 확인합니다. 실시간 서버 푸시가 아니라 설정한 정기 확인 간격으로 동기화합니다.
- 본문을 포함한 응답이 일시적으로 메모리에 들어올 수 있지만, 본문은 저장·출력·외부 전송하지 않습니다. 모델·사용 시각·중복 확인용 해시만 저장합니다. 동기화는 기본 OFF이며 사용자가 직접 켭니다.
- 공식 서버 잔여 횟수 조회가 아닙니다. 삭제·임시 대화와 모델 정보가 불명확한 기록은 빠질 수 있습니다. 일반 Sol Thinking은 Sol Pro로 세지 않으며, Pro 여부가 모호하면 미확인으로 표시합니다.
- 실제 ChatGPT 조회 경로는 비공식 웹 인터페이스입니다. 모의 테스트와 UI 검증을 통과해도 실제 계정의 기록 조회·기기 간 집계가 검증된 것은 아닙니다. 서버가 변경되거나 접근을 거부하면 기존 집계를 유지하며 오류를 표시합니다.

설치 폴더를 업데이트한 뒤 `chrome://extensions`에서 **Codex 리셋 레이더**를 새로고침하세요. 설정의 버전이 **0.2.24**인지 확인합니다. 기존 연결·테마·알림 설정은 유지되며 계정 기록 동기화는 별도로 켜야 합니다.

## Codex 리셋에 맞춰 Chat 카운터 초기화

설정의 **Codex 리셋 시 Chat 카운터도 초기화**가 기본으로 켜져 있습니다. **내 잔여량·리셋권**과 **Chat 계정 연결 및 모델별 카운터**도 켜져 있어야 동작합니다. 이미 연결한 0.2.22 사용자는 확장 관리 화면에서 새로고침하면 연결과 요금제·기록을 유지합니다.

- 같은 계정의 Codex 5시간 또는 주간 잔여량 회복을 실제 조회로 확인하면, Astra·Sol Pro의 이전 관측 기록을 집계에서 제외하고 다시 셉니다. 최초 조회가 100%인 것만으로는 초기화하지 않습니다.
- PC/Chrome 종료 뒤 확인된 리셋도 적용합니다. 예정된 경계가 넘어간 사실을 확인할 수 있으면 그 시각 이후 기록은 남깁니다. 비정기 리셋의 정확한 발생 시각은 알 수 없어 확인 시각을 기준으로 초기화합니다.
- 중복 조회·서비스 워커 재시작으로 다시 초기화하지 않습니다. 원래 응답 해시는 기존 30일·2,000개 보관 범위 안에서 유지하여 늦은 중복 응답을 다시 세지 않습니다.
- 알림을 꺼도 카운터는 동기화됩니다. 연동 옵션을 끄면 이후 리셋은 적용하지 않으며 다시 켰다고 과거 리셋을 재적용하지 않습니다.
- 팝업의 **Codex 연동 초기화 · 시각 기준**으로 반영 여부를 확인할 수 있습니다. 요금제는 각 계정에서 확인한 값을 그대로 사용합니다.

이 기능은 사용자가 요청한 **로컬 카운터 동기화**이며 Chat 서버의 실제 초기화를 검증하는 기능이 아닙니다. 공식 안내는 Chat과 Work/Codex의 한도를 별도로 설명합니다. 남은 횟수는 계속 추정치이며, 연결 전·다른 기기 사용량은 포함하지 못합니다. 참고: https://help.openai.com/en/articles/20001516-managing-usage-with-gpt-6-astra-in-work-and-codex (2026-09-20 확인).


## 계정별 요금제 자동 확인

Pro $100 고정값을 제거했습니다. 팝업의 **Chat 계정 연결**을 누르면 같은 Chrome의 ChatGPT 세션으로 계정을 식별하고, 새로 열린 **현재 구독(청구) 화면**에서 요금제를 자동 확인합니다. 요금제를 직접 선택하거나 금액을 입력하지 않습니다. 계정 식별 정보는 로컬 난수를 섞은 해시만 저장하며 원본 토큰·이메일·계정 ID는 보관하지 않습니다.

- ChatGPT Pro 5x 확인 → Pro $100 공유 주 50회.
- ChatGPT Pro 20x 확인 → Astra 주 200회, Sol Pro 일 170회, 두 모델 합산 일 200회를 함께 반영.
- Business Standard / Premium을 명확히 확인한 경우 각각 공유 월 15회 / 주 50회 기준. 다른 워크스페이스·불명확한 플랜은 잔여량 미확인.
- 단순 Pro, Plus, Free 등에서 정확한 모델별 한도를 확인하지 못하면 임의로 50회를 적용하지 않습니다.
- 응답 모델 식별자로 실제 Astra·Sol Pro 사용을 구분합니다. 기존 대화를 열었다고 횟수가 늘지 않으며 계정별 관측 기록을 분리합니다.

0.2.21의 계정 구분 없는 기록을 새 로그인 계정에 붙이지 않기 위해 Chat 기능은 다시 연결해야 합니다. 기존 Codex 계정 조회·Tibo·알림·테마 설정은 유지됩니다. Chrome 확장 관리에서 새로고침 후 팝업의 **계정 연결**을 누르세요. 열린 ChatGPT 현재 구독 페이지가 표시되면 확장을 다시 열어 결과를 확인합니다. 기존 ChatGPT 대화 탭도 새로고침하세요.

카운터는 이 Chrome에서 관측한 새 응답 기준의 **추정치**입니다. 켜기 전·다른 기기·재생성은 제외되며, 최근 24시간/7일/30일 창은 서버의 실제 초기화 주기와 다를 수 있습니다. 요금제 근거는 24시간이 지나면 재확인 전까지 잔여 계산에 사용하지 않습니다. 설정의 **요금제 다시 확인**으로 구독 변경 후 재연결할 수 있습니다.

공식 한도 근거: https://help.openai.com/en/articles/20001354-gpt-56-and-gpt-6-pro-in-chatgpt (2026-09-20 확인).

소식 카드는 reset / 후보 → 시간 언급 → 트윗 본문 → 원문 보기 순서이며, 시간은 오후 6:30처럼 표시합니다.

0.2.19는 테스트 버튼에 문구도 표시되지 않는 상황을 진단하도록 알림 테스트를 다른 설정 코드와 분리했습니다. 설정 → 알림에 ‘v0.2.19 테스트 버튼 준비 완료’가 표시되고, 실행 중인 백그라운드 코드 버전·Chrome 알림 허용·후보 알림 켜짐·대기 개수를 확인합니다. 버튼을 누르면 즉시 동작 문구를 표시하며 10초 응답 제한을 적용합니다. 이전 실행 코드나 끊어진 설정 탭도 구분하여 안내합니다. 테스트는 계정·피드 초기화에 의존하지 않고 설정을 바꾸지 않습니다.

알림 아이콘은 빌드 시 검증한 PNG를 데이터 URL로 코드에 포함합니다. 알림 시 파일 경로를 다시 읽지 않으며, 이전 대기열의 보조 이미지·버튼 이미지 경로도 제거합니다. 이를 위해 connect-src에 data:만 추가하며 외부 호스트와 권한은 늘리지 않습니다. 소리 사용을 요청하지만 Windows의 방해 금지·소리·알림 허용 설정은 변경하지 않습니다.

Chrome의 마지막 전달 결과(접수 또는 실패), 오류 종류·시각·버전·테스트 여부만 로컬에 1건 저장하고, 팝업에 최근 전달 실패를 표시합니다. 접수는 Chrome API의 성공 응답이며 Windows 배너나 소리가 실제로 표시됐다는 뜻은 아닙니다. ‘Chrome 접수’인데도 안 보이면 Windows의 Chrome 알림 허용·배너·방해 금지를 확인하세요. 테스트 기능은 자동으로 알림을 보내지 않으며 직접 버튼을 눌러야 합니다.

0.2.18은 Chrome의 “Unable to download all specified images” 알림 오류를 수정합니다. 알림 아이콘을 확장 루트의 절대 URL로 지정하고, 서비스 워커가 자기 확장의 PNG를 읽도록 connect-src에 'self'만 추가했습니다. 외부 호스트·선택 권한은 늘리지 않았습니다. 이전 버전에서 대기하던 알림도 전달 시 새 경로를 사용합니다.

시스템 알림 실패가 데이터 조회 실패로 잘못 처리되거나 이후 알림을 중단하지 않도록, 실패한 알림을 기존 대기열(최대 10개)에 보관하고 다음 확인에서 재시도합니다. 설정 동의·방해 금지·후보 유효기간·계정 재확인 조건은 유지합니다. 설정 → 알림 → **테스트 알림**으로 바로 점검할 수 있습니다. 테스트는 감시 설정을 바꾸거나 계정을 조회하지 않으며, 실패한 테스트를 자동 재전송하지 않습니다. Chrome이 요청을 수락해도 Windows 알림 차단·방해 금지에 따라 화면이나 소리가 다를 수 있습니다.

업데이트 후 chrome://extensions/에서 확장 새로고침을 누르고 설정 탭도 F5로 갱신하세요. Chrome 오류 목록에 남은 과거 기록은 수정 후에도 자동으로 사라지지 않을 수 있습니다.

0.2.17은 Chrome 시작 후 놓친 공개 리셋 예고·암시를 다시 확인합니다. Tibo 수집 실패·오래된 피드는 다른 출처가 성공해도 팝업에 따로 표시합니다. 최신 수집 글이 3일보다 오래됐다는 표시는 수집 지연 가능성을 뜻하며, Tibo가 글을 쓰지 않았을 가능성도 있습니다. 후보 표시·알림 대상은 최근 7일, 최대 3개로 늘렸습니다. 팝업은 가장 최근 후보 1개를 보여줍니다. 계정 조회와 무관하게 작동하며, Chrome 시작 직후 최근 글을 확인하지 못하면 1·2·5·10·15분 간격으로 최대 5회 추가 확인합니다. 팝업을 열 때 1분 이상 지난 공개 소식도 갱신합니다.

설정 → 감시 설정 → **X 공개 페이지 직접 확인**은 기본 꺼짐입니다. 켤 때 Chrome의 선택 권한(scripting, x.com)을 요청합니다. 허용하면 정기 확인·복귀 확인 때 Tibo의 공개 글·답글 목록을 비활성 탭으로 잠깐 열어 읽고 닫습니다. 같은 Chrome 프로필의 X 로그인이 필요할 수 있습니다. 화면에 처음 로드된 최근 글만 확인하며 모든 글이나 7일치 전체 수집을 보장하지 않습니다. DM·쿠키·인증 정보를 읽거나 외부 AI에 전송하지 않습니다. 허용 뒤 **공개 소식 확인**을 눌러 연결을 확인하세요.

리셋권 요청 주변에서 동의·미래 일정을 말하는 Tibo 답글은 **문맥 연결 추정 · 미확인 후보**로 표시합니다. 옆에 나온 글이 실제 부모 글인지는 확정하지 않으며, 제품 발표와 리셋을 혼동하지 않도록 리셋 예고·예상 시각으로 승격하지 않습니다. 알려진 규칙과 문맥 조건에 의한 무료 감지이므로 처음 보는 모든 비유를 이해하지는 못합니다.

설정 → 알림 → **은유·암시 후보 알림**은 기존처럼 기본 꺼짐이며, 켜면 다음 조회에서 최근 후보도 한 번 알립니다. **놓친 공개 소식 복귀 알림**은 기본 켜짐으로 복귀 때 확인한 예고·암시의 확장 방해 금지 시간을 예외 처리합니다. 늦게 수집한 후보도 이 설정을 적용합니다. 후보 알림 자체가 꺼져 있으면 화면에만 표시합니다. Windows 알림 차단은 우회하지 않습니다. PC가 꺼져 있을 때는 동작하지 않으며 **Chrome을 다시 실행한 후** 확인합니다. 일정 변경 알림의 기존 12시간·48시간 기준은 그대로입니다.

0.2.16은 PC 종료·절전·Chrome 종료 뒤 놓친 잔여량 회복을 다음 조회에서 확인해 알립니다. 이전 비교 기록을 최대 30일 유지하고, Chrome 시작 직후 인터넷 연결이 실패하면 1·2·5·10·15분 간격으로 최대 5회 추가 재시도한 뒤 기존 주기적 확인을 계속합니다. 팝업을 열 때도 1분 이상 오래된 계정 조회값을 갱신합니다.

설정 → 알림 → **다시 켰을 때 놓친 회복 바로 알림**은 기본 켜짐입니다. 복귀 시 같은 계정의 회복을 확인하면 확장의 방해 금지 시간에도 알립니다. 끄면 회복 알림이 방해 금지 종료 뒤로 미뤄집니다. Windows 자체 방해 금지·Chrome 알림 차단은 우회하지 않습니다. **PC를 켠 뒤 Chrome이 실행되어야 합니다.**

이미 리셋 뒤 일부를 사용했더라도 이전 초기화 시각이 지났고 다음 주기로 바뀌었으며 잔여량이 늘어난 것을 확인하면 현재 잔여량으로 안내합니다. 예정 시각만 지났다는 이유로 100% 회복을 가정하지 않습니다. 첫 연결, 30일 이상 지난 비교 기준, 명시적 로그아웃 후 재연결, 비교 불가능한 계정·요금제 변경은 새 기준만 저장합니다. 이전 버전에서 이미 사라진 비교 기록이나 그 사이 여러 번의 리셋 내역은 복원할 수 없습니다.

## 설치·업데이트

1. ZIP을 고정된 폴더에 압축 해제합니다. 준비된 CodexReset-Radar-KO 폴더도 사용할 수 있습니다.
2. Chrome 주소창에 chrome://extensions/를 입력하고 개발자 모드를 켭니다.
3. 처음 설치하면 ‘압축해제된 확장 프로그램을 로드합니다’에서 manifest.json이 바로 들어 있는 폴더를 선택합니다. 기존 설치 폴더의 파일을 교체했다면 해당 확장의 새로고침(⟳)을 누릅니다.
4. 버전 0.2.19을 확인합니다. 이미 열려 있던 설정 탭도 F5로 새로고침하세요.
5. 같은 Chrome 프로필에서 [Codex 사용량 페이지](https://chatgpt.com/codex/settings/usage)에 로그인합니다.
6. 확장의 설정에서 ‘내 잔여량·리셋권’을 켜고 팝업의 ‘지금 확인’을 누릅니다. 첫 실행 안내의 ‘내 한도 연결하기’로도 켤 수 있습니다.

**처음 설치하거나 0.2.3 이하에서 업데이트하면 계정 조회가 꺼져 있습니다. 직접 켜야 잔여량을 조회합니다. 0.2.4·0.2.5에서 업데이트할 때는 기존 연결 설정을 유지합니다.** 공개 소식만 볼 때는 계정 연결이 필요 없습니다. 설치 폴더를 이동·삭제하지 마세요. 다른 버전도 설치했다면 사용할 버전만 켜서 중복 알림을 피하세요.

## 0.2.12 리셋 일정 변경 알림

기존에 감지한 Tibo의 명시 예고 또는 은유 후보에 후속 연기·일정 변경 글이 연결되면 팝업에서 이전 글과 변경 글을 표시합니다. 같은 게시물의 수정, 답글·인용 게시물 ID를 우선 사용합니다. 연결 정보가 없으면 최근 48시간 안의 같은 대상 예고가 정확히 하나일 때만 연결하며, **연결 추정**이라고 표시합니다. 여러 후보가 있거나 다른 스레드를 가리키면 자동 연결하지 않습니다.

- 연결된 이전 신호와 변경 글은 기존 시간 예상·계정 사용 안내에서 제외하고 이전 알림·대기 알림·한 시간 뒤 재알림을 중단합니다. 다른 독립 신호는 유지합니다.
- 새 정확한 시각은 만들어내지 않습니다. 변경 글과 게시 시각을 함께 보여주며, tomorrow 같은 상대 표현은 게시글 기준으로 읽어야 합니다.
- 설정 → 알림 → **리셋 일정 변경 알림**은 기본 켜짐입니다. 명시 예고는 기존 예고 알림이 켜져 있을 때, 은유 후보는 기존 후보 알림이 켜져 있을 때만 알립니다.
- 기존 확인 간격(기본 30분)으로 확인합니다. 즉시 푸시는 아니며 방해 금지 시간을 따릅니다. 게시 후 12시간 내 변경 글을 알리고, 대기 알림은 근거가 최신인 동안만 전달합니다.
- 같은 글·내용은 반복 알림을 보내지 않습니다. 다시 미뤄지는 새 글이나 내용 수정은 별도 변경으로 처리합니다. 수정되어 연기 표현이 사라지면 해당 변경 근거와 대기·표시 알림을 제거합니다. 피드 조회 실패나 글의 일시 누락은 철회로 간주하지 않습니다.
- 관련 공개 글은 로컬에 최대 7일·30개 사건, 사건당 변경 8개까지 보관합니다. 최근 변경 카드는 게시 후 48시간 동안 표시합니다. 계정 데이터나 새 서버는 추가하지 않습니다. 공개 소식 또는 Tibo 감시를 끄거나 데이터 지우기를 실행하면 변경 기록을 지웁니다.
- 작성자와 답글·인용 정보는 기존 공개 피드 제공값이며 X에서 별도로 검증하지 않습니다. 정보가 누락되거나 새로운 은유·이미지에만 표현된 연기는 놓칠 수 있습니다. 은유 후보는 리셋 확정으로 승격하지 않습니다.

## 0.2.6 은유 감지 개선

팝업은 밝은 바탕, 큰 잔여량 숫자, 얇은 구분선으로 정리했습니다. 리셋권·예상 시간대·상세 안내는 펼쳐서 봅니다. 검증된 정확도가 아닌 예측 퍼센트는 화면에서 제거했습니다.

사용자가 제공한 Tibo_Codex_Reset_Data.json의 게시물 89건과 실제 영어 발췌 24건을 검토하여 로컬 규칙을 보강했습니다. 전문은 0건, 실제 계정 리셋 독립 검증도 0건이므로 AI 학습·예측 정확도 평가 자료로 취급하지 않았습니다. 전문이 없는 65건의 한국어 요약을 원문처럼 사용하거나, 후속 완료 글을 당시 판정에 넣지 않습니다. 원본 자료와 테스트용 발췌는 설치 ZIP에 포함하지 않습니다.

| 표현·맥락 | 처리 |
| --- | --- |
| “Who says … won't reset …” 같은 반문 | 실제 부정문과 구분한 낮은 신뢰의 후보 |
| 새 이정표 + 축하 + 미래 표현 | 알려진 축하 표현과 유사한 후보. 실제 리셋 대상은 미확인 |
| Codex·한도 맥락 + 선물·놀라움 예고 | 내용 미확인 후보. 굿즈·팬 선물·당첨·경품 제외 |
| 리셋 맥락 + 축하 일정 연기 | 일정 변경 후보. 과거 완료와 별도로 구분 |

‘Little surprise for you tomorrow’, ‘Soon, but not today’, ‘find it tomorrow and dust it up’, ‘Yes’, ‘Thanks!’만 있는 글은 대상이 불명확하므로 자동 후보로 올리지 않습니다. 문맥을 못 찾은 글을 ‘리셋이 일어나지 않은 사례’로 판정하는 것은 아닙니다. 기존 Codex 문맥의 연료·충전·새 출발 규칙도 유지합니다.

알려진 비유는 명시 예고와 별개인 ‘Tibo 암시 후보’로 표시합니다. 0.2.17부터 최근 7일 이내의 지정 공개 피드 또는 선택한 X 직접 확인에서 작성자가 thsottiaux로 표시된 글만 검사합니다. 피드의 작성자 정보는 X에서 별도로 인증한 결과가 아닙니다. 계정별 실제 복구 여부도 확인한 것이 아닙니다.

후보는 최신 100개까지 로컬에 보관하고 팝업에는 보관된 유효한 후보를 최신순으로 보여줍니다. 후보 알림은 최신 3개 범위를 유지합니다. 리셋 확정·확률 계산·계정 사용 안내에는 넣지 않습니다. 기본으로 알림은 꺼져 있으며 설정 → 알림 → ‘은유·암시 후보 알림’을 켜면 다음 조회에서 게시 후 7일 이내의 보관 후보도 알릴 수 있습니다. 일반 알림은 방해 금지 시간을 따르고 놓친 공개 소식 복귀 알림은 설정에 따라 예외 처리하며 게시물 ID당 최대 1회 알립니다. 기존 글이 수정되어 뒤늦게 후보가 된 경우도 반영합니다. 철회·수정·만료로 목록에서 빠진 후보의 대기·표시 알림은 제거합니다. 다른 ID로 재게시한 같은 사건까지 묶어 중복 제거하는 기능은 없습니다.

업데이트 시 저장된 명시 신호도 새 규칙으로 재판정합니다. 이전 버전이 ‘오늘은 아님’을 몇 시간 뒤 예고로 저장했던 경우 후보로 낮추고 기존 명시 알림과 재알림을 차단합니다. 새로운 명시 리셋 예고는 완료 문장과 미래 리셋 문장을 구분해 판정합니다.

무료 로컬 규칙이며 AI API와 새 외부 서버는 없습니다. 처음 보는 은유, 이미지, 상위/인용/답글 문맥은 이해하지 못할 수 있습니다. 이 규칙을 모든 은유의 탐지율이나 예측 정확도로 해석하면 안 됩니다. 예시 문장에 대한 회귀 테스트는 실제 리셋 결과로 검증한 정확도 평가가 아닙니다.

## 보안 강화 내용

- 페이지에서 토큰을 읽던 구형 기능을 제거했습니다. 계정 API 조회는 백그라운드에서만 수행하며, 선택형 Chat 카운터는 별도 동의 후 페이지의 모델·응답 식별자만 관측합니다.
- 로그인 토큰은 조회 요청 중 메모리에서만 사용하며 확장 저장소에 보관하지 않습니다. 이전 버전의 토큰 캐시도 삭제합니다.
- 계정 조회 OFF 시 진행 중인 요청을 취소하고, 계정 표시 데이터·관련 알림과 중복 방지 기록을 지웁니다. 늦게 도착한 응답의 재저장을 차단합니다.
- 메시지 발신 확장·화면·프레임과 입력값을 검사합니다. 임의 조회 주소와 이전 토큰 전달 메시지를 받지 않습니다.
- 근거 링크는 HTTPS와 출처별 도메인·게시물 경로를 검증한 뒤 엽니다.
- 공개 피드 API 요청에는 쿠키·로그인 토큰·참조 주소를 보내지 않습니다. 선택 기능인 X 직접 확인은 일반 브라우저 탭에서 기존 X 세션으로 페이지를 열지만 확장이 쿠키나 토큰을 읽지 않습니다. 고정된 조회 주소, GET, 리디렉션 거부, 15초 제한과 응답 크기 제한을 적용합니다.
- 불필요한 tabs 권한과 웹 접근 가능 리소스를 제거하고 확장 페이지의 콘텐츠 보안 정책을 명시했습니다.
- 개발 의존성을 패치하고 다운로드 주소를 공식 npm으로 통일했습니다.

## 사용과 알림

팝업에서 공개 리셋 소식, 예상 시간대, 계정 연결 시 5시간·주간 잔여량 및 초기화 시각, 리셋권 개수·만료 예정 시각을 확인합니다. API 키는 필요 없습니다. 브라우저 언어와 무관하게 화면과 알림은 한국어입니다. 외부 게시글 원문은 자동 번역하지 않습니다.

설정은 자동 저장됩니다.

| 항목 | 기본값 |
| --- | --- |
| 계정 조회 | 꺼짐. 명시적으로 연결한 뒤 켜짐 |
| 공개 소식 조회 | 켜짐. 제공처별로 끌 수 있음 |
| X 공개 페이지 직접 확인 | 꺼짐. 직접 켜고 선택 권한 허용 필요 |
| 은유·암시 후보 알림 | 꺼짐. 후보는 팝업에 표시 |
| 놓친 공개 소식 복귀 알림 | 켜짐. 해당 예고·후보 알림을 켠 경우에만 전달 |
| 확인 간격 | 30분. 15분·30분·60분·2시간 선택 |
| 공개 소식 알림 | 신뢰도 높음 |
| 잔여량 회복 알림 | 켜짐. 계정 조회가 켜져 있어야 작동 |
| 리셋권 만료·잔여량 부족 안내 | 켜짐. 계정 조회가 켜져 있어야 작동 |
| 복귀 시 놓친 회복 바로 알림 | 켜짐. 확장 방해 금지 시간에도 전달 |
| 방해 금지 시간 | 23:00–08:00 |
| 표시 시간대 | 시스템 따름. 수동으로 Asia/Seoul 설정 가능 |

알림은 Chrome 시스템 알림을 사용합니다. Windows의 Chrome 알림 허용 설정에 영향을 받습니다. 브라우저 종료·PC 절전·공개 제공처 갱신 지연 시 확인도 지연됩니다. 즉시 푸시가 아닌 주기적 조회 방식입니다.

공개 자료에 따른 리셋 예측과 **내 잔여량의 실제 회복 확인**은 별도입니다. 회복 알림 예: ‘Codex 잔여량이 100%로 리셋됐어요 — 주간 27% → 100%. [확인 시각] 조회값입니다.’ Tibo가 예고하지 않은 회복도 감지하며, 회복의 원인까지 판정하지는 않습니다.

비교 기록이 없는 계정의 첫 조회는 기준만 저장합니다. 기존 0.2.14 이후 비교 기록은 업데이트 뒤에도 이어서 사용합니다. 같은 100% 상태는 다시 알리지 않고 다시 사용한 뒤 회복되면 새 알림을 보냅니다. 5시간·주간이 함께 회복되면 하나로 묶습니다. 화면 반올림이나 예정 시각만으로 리셋을 단정하지 않습니다.

일반 회복 알림은 방해 금지 중 보류하며 같은 계정의 조회가 다시 성공해야 전달합니다. 복귀 알림 설정이 켜져 있으면 Chrome 재시작 또는 확인 간격의 두 배를 넘는 공백 뒤 확인한 회복은 확장 방해 금지 시간에도 전달합니다. 기록은 최근 30일·최대 8건만 비교·알림에 사용합니다. 회복 뒤 다시 사용하여 잔여량 증가를 확인할 수 없거나 로그인·네트워크 오류가 지속되면 알리지 못할 수 있습니다. 알림 소리는 Windows와 Chrome의 설정을 따릅니다.

## 개인정보와 연결

사용자가 계정 조회를 켜면 ChatGPT 로그인 세션과 사용량·리셋권 API를 백그라운드에서 읽습니다. 기존 Chrome 로그인 쿠키를 이용하며 로그인 토큰을 별도 서버로 보내지 않습니다. 저장하는 계정 정보는 잔여량·시간·요금제·리셋권 요약과 회복 비교 기준·알림 기록입니다. 계정 전환 오탐을 막기 위한 로컬 난수와 SHA-256 계정 비교값도 저장합니다. 원본 토큰·전체 계정 ID·사용자 ID는 저장하지 않습니다. 자세한 생성 방식과 삭제 조건은 PRIVACY.md에 있습니다.

공개 정보는 Dayclaw, OpenAI Status, codex-resets.com, GitHub에서 조회하며 선택 기능을 켜면 X 공개 페이지도 읽습니다. 제공처는 접속 IP와 요청 시각 등을 볼 수 있으며 그 서버 운영까지 검증한 것은 아닙니다. 분석 추적, 별도 운영 서버, 리셋권 자동 사용, 계정 변경 요청은 없습니다. 자세한 처리 내용은 PRIVACY.md를 확인하세요.

ChatGPT 조회 경로는 공식 공개 연동 API가 아니므로 변경이나 브라우저 쿠키 정책 때문에 실패할 수 있습니다. 실제 로그인 계정에서의 조회 성공 및 Windows 알림 표시는 이번 모의 검증에 포함되지 않았습니다.
